# Rust

## Проверка входа

- `unsafe` блок — только когда есть реальная причина, не «на всякий случай»
- `unsafe impl` — с обоснованием инварианта, который ты поддерживаешь
- Комментарий `// SAFETY:` обязателен перед каждым `unsafe` блоком

## Паника

Паника в FFI-функции уносит процесс вызывающей стороны. Если функция
экспортируется наружу (C ABI, plugin API) — не бросай панику через границу.
Лови и возвращай код ошибки.

## FFI: экспорт для C ABI

```rust
// SAFETY: единственное определение этого символа в процессе
#[unsafe(no_mangle)]
pub extern "C" fn add(a: i32, b: i32) -> i32 {
    a + b
}
```

`no_mangle`, `export_name` и `link_section` требуют обёртки `unsafe(...)`
начиная с Rust 2024. Без неё — ошибка компиляции, не предупреждение.

Строки наружу — `*const c_char`. FFI не знает Rust-типов. Собственная
структура наружу требует `#[repr(C)]`, иначе layout не гарантирован.

Границу моста держи тонкой: в C — сигнатуры и структуры, без логики.

## Со стороны bun: bun:ffi

```ts
import { dlopen, FFIType } from "bun:ffi"

const lib = dlopen("./libfoo.so", {
  add: { args: [FFIType.i32, FFIType.i32], returns: FFIType.i32 },
})
```

- `FFIType` описывает типы точно. Неверное описание = чтение мусора из памяти
- Числа передавай числами, не указателями
- Возвращаемый указатель требует явного владения. Не отдавай наружу указатель
  на локальный буфер

Вызов через FFI в горячем цикле дорог. Выноси в цикл Rust, в JS оставь
один вызов на пачку данных.

## Async: tokio

- Не блокируй внутри async. `std::thread::sleep` вместо `tokio::time::sleep`
  в async-функции стопорит рантайм
- `std::sync::Mutex` внутри async — источник висяков. `tokio::sync::Mutex`
- `spawn_blocking` для CPU-тяжёлого и sync-кода
- Structured concurrency: не оставляй таски без владельца и без отмены

## Ошибки

- `unwrap()` и `expect()` в library-коде — ошибка. В test и main — допустимо
- Не глотай `Result`. Если игнорируешь — объясни в коде почему
- `?` вместо ручной проверки каждой ошибки

## target/

Не читай и не правь руками. Собирай командами: `cargo build`, `cargo check`,
`cargo clippy`, `cargo test`. Искусные тайминги и разбор артефактов сборки
вручную — не то, чем занимается агент.

## Проверка

- `cargo check` — быстрая проверка компиляции
- `cargo clippy` — линтер
- `cargo test` — тесты
- `cargo fmt` — форматирование
